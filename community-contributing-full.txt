# Labs64.IO Community & Contributing

Labs64.IO is many repositories, not one. A change belongs to the repository that owns what you are changing, and each pull request stays within one repository: fork it, push a branch, open a pull request against master.

Documentation fixes: use "Edit this page on GitHub" at the bottom of any page. Bugs and feature requests: open an issue in the owning repository. A change to one service: work in that service's repository; each builds and tests on its own (just --list shows the commands, usually just up and just test). A change across services or to the Helm charts: use the Labs64.IO Workspace, which clones every repository side by side and builds and runs them in a local k3d cluster (just doctor, just clone, just up).

Conventions enforced by build or review: APIs are OpenAPI-first and generated code is never edited; no credentials in code; images run as a non-root user; services do not add an OpenTelemetry SDK; each service owns its data; a chart change bumps the chart version (just bump <chart>); versions have one owner each.

Service repositories own service-specific source. Helm charts contain Kubernetes packaging and the installer; Labs64.IO Commons contains shared libraries; the docs repository contains public documentation. Start at /docs/development/ for the contributing guide, the repository list, releases and versions, testing, and the shared libraries.
